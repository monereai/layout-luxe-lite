# Treasure adventure rules
- Quest completion derives from saved rescued state and pauses gameplay; explicit restart serializes pending actions, resets adventure/cache/canvas state via authenticated treasure_restart, and never clears reward ledgers or account inventory. Why: completion and replay must not loop or duplicate rewards.
- Treasure tap routes use the shared collision pathfinder; locked answer stones route to the inner-door approach and explain prerequisites. Why: visible scenery must not silently swallow navigation or bypass gate rules.
- Tree interactions pause world/side-land controls while the browser-only Phaser harvesting dialog is open; safe expulsion restores only position, never quest progress or inventory. Why: maze keyboard input must not also move the world player.
- All tree interactions use the shared PacmanHarvestMiniGame onComplete callback carrying collected Energy and its replay trace; the HUD accepts only settled account Energy, never a client-reported reward. Why: legacy direct harvest paths must not bypass the maze or verified payouts.
- Crystal Gate and World Map Crystal entry call the same direct maze transition, never mount SideZone for caverns, and return to the main map on settlement or entry failure. Why: a failed or delayed round must not expose the retired cave/tree interaction.
- Only the authenticated Crystal start's exact daily-ledger refusal authorizes a no-reward practice session; practice never calls settlement or updates care. Why: repeat entry must remain playable without bypassing identity, location or daily reward checks.
- Smooth world movement follows only collision-approved corridor endpoints; authenticated sprint/dash spend Energy atomically before enabling visual speed boosts, and maze animation preserves its deterministic tick trace. Why: animation must not forge travel, Energy or rewards.
- Save-specific huntSpots select three key-fragment digs from the shared twelve-coordinate pool; SQL generates and validates account placements while existing progressed saves retain their old positions. Why: replayability must not strand gear quests or invalidate saved collections.
- Harvest best scores are account-keyed local display records, never a source for Energy or account rewards. Why: local persistence must not become a payment or reward authority.
